# dsh-glob-replace

This plugin was generated by DeepSeek V4.1 Flash 1017.

Glob-scoped search and replace for DeepSeek Harness. One tool call rewrites
every file matching a path glob, instead of routing a bulk edit through
`sed`/`awk`/`python` and losing the diff.

The tool is `glob_replace`:

```json
{
  "glob": "src/**/*.ts",
  "pattern": "\\boldName\\b",
  "replacement": "newName"
}
```

- Literal matching: add `"literal": true` to replace an exact string.
- Regex matching (default) is JavaScript syntax and replaces globally; `$1`,
  `$&`, and `$$` work in `replacement`.
- `path` selects the search root (default: the session working directory).
- `exclude` accepts glob patterns such as `["**/*.test.ts"]`.
- `dry_run` reports counts and diffs without writing.
- `max_files` (default 100, max 500) and `max_file_bytes` (default 1 MiB)
  bound the call.
- `sandbox_permissions` + `justification` mirror `write`/`edit`: when the
  sandbox denies a write, retry the exact call once with the narrowest wider
  mode. The approval prompt covers this one call (the whole batch), and the
  denial marker plus escalation hint match the built-in tools. The escalation
  vocabulary is a zero-dependency mirror of `@deepseek-ai/dsh-sandbox`, so no
  extra package is installed.

Every changed file is written through `ctx.fs` with the same path as
`edit`/`write`: resolve → read → `fs/observed` → `fs/write-intent` → atomic
write. That keeps the sandbox, the read-before-write policy, the
workspace-changes capture, and the per-file diff provenance intact.

The result lists each changed file with its replacement count and a bounded
unified diff. `.git`, other VCS metadata, and `node_modules` are never
searched. Binary files, oversized files, and files over the per-file match cap
are reported as skipped.

The package also ships a browser half (`client.js`, hand-written in DSH's
client-module format). It registers a `tool.call.toolview` for `glob_replace`
that renders `meta.diffs` with the exported `DiffBlock` primitive — the same
component the built-in `write`/`edit` rows use — inside the exported
`DisclosureRow` chrome. No core patch and no copied diff renderer: the card is
unified across `write`, `edit`, and `glob_replace`.

For renaming a code identifier, prefer an LSP rename tool when one is
configured — it respects scope and leaves strings and comments alone. Use
`glob_replace` for text that is not a symbol: log messages, config keys, docs,
comments, import paths, and code in languages without a language server.

## Install

From a local checkout:

```sh
dsh plugin --profile <name> add /absolute/path/to/glob-replace
```

In the Desktop app, install the same absolute path through the plugin manager
(Settings → Plugins). The profile records a `link:` dependency and adds
`dsh-glob-replace` to `dsh.profile.bundles`, so the tool appears in new
sessions. Because the module is linked, a code edit is picked up after a
bundle reload (disable/enable the plugin) or an app restart — no reinstall.
Client bundles are fetched when the page boots, so after changing `client.js`
refresh the Web UI once; the host tool needs only the bundle reload.

## Development

```sh
node --test test/
```

The tests cover glob compilation, literal and regex replacement, dry-run,
exclusion, truncation, and diff hunks against a temporary file tree.
